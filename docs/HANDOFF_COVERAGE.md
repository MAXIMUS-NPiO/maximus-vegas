# Карта покрытия технического handoff

Title: Handoff coverage map · Status: PENDING MIPA REGISTRATION · Version: 1.0 · Date: 27 September 2026

Источник требований — «Maximus Vegas — Technical Handoff & Requirements Spec» (разделы 3–9). Эталонная реализация из архива `maximus-vegas-backend.zip` (Express + SQLite) использована как описание логики и перенесена в стек портала (Next.js + PostgreSQL); отдельный сервер Express не развёртывается.

Статусы: **Реализовано** — работает в коде и покрыто тестами; **Изменено** — реализовано с отличием, указана причина; **Исключено** — не реализуется по решению; **NOT PROVIDED** — нужны внешние данные или доступы.

## Раздел 3. Турниры

| Требование | Статус | Где / почему |
| --- | --- | --- |
| 3.1 Жизненный цикл DRAFT → … → COMPLETED, CANCELLED, ARCHIVED | Реализовано | `src/server/tournaments.ts`, таблица переходов; для leaderboard завершение из IN_PROGRESS |
| 3.1 Баннер, описание, максимум участников, команды, ссылка трансляции | Реализовано | Баннер — `tournament.banner`, трансляция — `livestream_url` |
| 3.1 Тип входа «платный», взнос за участие | Исключено | Письмо MAXIMUS VEGAS от 30 June 2026; условия, раздел 3: участие бесплатно |
| 3.1 Призовой фонд | Изменено | Награда победителю в монетах, назначает оператор; текстовое описание призов организатора; фондов из взносов нет |
| 3.2 Посев не случайный: навык, затем порядок регистрации | Реализовано | Ручной посев → XP в этой игре → время регистрации |
| 3.2 Каскадные проходы без игры | Реализовано | `tests/bracket.test.ts`, `tests/engine.test.ts` |
| 3.3 Нижняя сетка: 2(k−1) раундов, раунд 0, вливание в нечётных, консолидация в чётных | Реализовано | `src/server/double.ts`; формы сетки для 2, 4, 8, 16 и полный прогон 2–64 (`tests/formats.test.ts`), 2–12 на базе |
| 3.3 Гранд-финал и перезапуск только при победе чемпиона нижней сетки | Реализовано | Перезапуск создаётся лениво (`GF`, раунд 2) |
| 3.3 Проигравший «прохода без игры» не попадает в нижнюю сетку | Реализовано | Анализ пустых слотов при построении |
| 3.4 Веса, best-of-N, окно самостоятельной отправки с живым отсчётом | Реализовано | `src/server/scoring.ts`, `leaderboard.ts`; отсчёт — `Countdown` на странице турнира |
| 3.5 Сортировка: очки → KDA → убийства | Реализовано | `standings()`; общие места при полном равенстве |
| 3.6 Два пути записи: организатор и сам участник | Реализовано | `score.log`, `score.submit`; самостоятельная отправка закрывается по сроку |
| 3.7 Check-in к матчу — информационный | Реализовано | `match.checkin`; не блокирует решение организатора |
| 3.8 Лист ожидания с продвижением при любом удалении до старта | Реализовано | Отзыв заявки и дисквалификация до старта (`promoteFromWaitlist`) |
| 3.8 Ограничение по странам с понятным сообщением | Реализовано | `country_required`, `region_locked`; страна — ISO-код в профиле |

## Раздел 5. Споры

| Требование | Статус | Где |
| --- | --- | --- |
| Оспаривание решённого матча участником с описанием и изображением | Реализовано | `dispute.file`; изображение видят только участники матча, его организаторы и сотрудники |
| Оставить в силе / отменить; одинаково для всех форматов и подсеток DE | Реализовано | `rewriteWinner`: верхняя и нижняя сетка, гранд-финал, перезапуск |
| Отмена матча, определяющего чемпиона, выплачивает награду новому чемпиону без списания у прежнего | Реализовано | `settleChampionAward`, ключ — регистрация чемпиона |
| Репутация: минус за претензии, оставленные без удовлетворения; обоснованные не штрафуются | Реализовано | 100 − 5 × число; показывается в профиле |

## Раздел 6. Античит и проверка статистики

| Требование | Статус | Где / почему |
| --- | --- | --- |
| Античит в реальном времени | Исключено | Не создаётся веб-сайтом (так и в handoff); на портале не заявляется |
| Проверка через PUBG API, разбор CS2 demo, фильтр убийств ботов | NOT PROVIDED | Нужны ключи и серверная интеграция по каждой игре; статус «исследование» |
| Слой флагов: невозможные и неправдоподобные строки на проверку | Реализовано | Пороги из handoff; строка не учитывается до решения; завершение блокируется |

## Раздел 7. Дополнительные системы

| Требование | Статус | Где / почему |
| --- | --- | --- |
| 7.1 Команды: приглашения, исключение, логотип и баннер, сводная статистика | Реализовано | `team.media`, статистика на странице команды |
| 7.1 Капитан — только метка | Изменено | Капитан сохраняет операционные права release 1 (приглашения, заявка команды); владение — у владельца |
| 7.2 Со-организаторы; добавляет и снимает только основной организатор | Реализовано | `tournament.coorg_add` / `_remove` |
| 7.3 Ранги и сезонный пропуск (бесплатная и премиальная линия) | Реализовано | `src/server/progression.ts`; премиум — за монеты или по членству |
| 7.4 Цели, проверяемые по фактическому состоянию | Реализовано | Проверка в момент получения, выплата один раз |
| 7.5 Кошелёк и косметика за монеты | Реализовано | Журнал монет, баланс не уходит в минус |
| 7.5 Магазин покупки монет | Исключено | Монеты не покупаются (условия, раздел 6) |
| 7.5 Автоматическая выплата чемпиону | Изменено | Монеты, назначенные оператором; не из взносов |
| 7.6 Членство | Изменено | Только косметика и премиальная линия пропуска; «скидка на взносы» исключена, так как взносов нет. Заявка → решение → счёт → оплата; оплата выключена до утверждённых условий и подтверждённого мерчанта |
| 7.7 Вызовы со ставками монетами | Изменено | Вызовы без ставок; победа даёт XP |
| 7.7 Быстрый матч с реальным игроком, без ставок | Реализовано | Очередь по игре, 30 минут ожидания |
| 7.8 Реферальный код, один ввод, проверка второй стороны | Реализовано | Награда пригласившему — после первого подтверждённого матча приглашённого |
| 7.9 Поиск: турниры, команды, игроки, FAQ | Реализовано | `/search` |
| 7.9 Поиск по блогу | NOT PROVIDED | Блога на портале нет |
| 7.10 Спонсоры: записи администратора, привязка к турнирам, полоса на главной | Реализовано | Полоса показывается только при активных записях |
| 7.11 Онбординг из 4 шагов, пропускаемый, только для новых аккаунтов | Реализовано | `/welcome`; существующим аккаунтам дата онбординга заполнена миграцией |
| 7.11 Вход через Google, Steam, Epic | NOT PROVIDED | Нужны зарегистрированные приложения; кнопки не показываются, имитации нет |

## Раздел 8. Найденные ошибки прототипа

| № | Защита | Где |
| --- | --- | --- |
| 1 | Идемпотентность выплаты по чемпиону, а не по турниру | `tournament_awards`, тест отмены гранд-финала |
| 2 | Продвижение из листа ожидания во всех путях удаления | `withdraw`, `disqualify` до старта |
| 3 | Различимые кнопки добавления команды и со-организатора | «Добавить со-организатора» — отдельная форма и подпись |
| 4 | OAuth не подменяется полем «запомнить меня» | OAuth не реализован; имитации нет |
| 5 | Согласованные выпадающие панели | Заголовок закрывает остальные панели при открытии одной, Escape и клик вне закрывают все |
| 6 | Панель у верхнего края раскрывается вниз | Панели навигации позиционируются под кнопкой |
| 7 | Значения по умолчанию из одного источника | Веса всегда сливаются с `DEFAULT_WEIGHTS` при расчёте |
| 8 | Сохранённое состояние дополняется текущими значениями по умолчанию | `mergeWeights`; тест «stored weights merge over defaults» |
| 9 | Привязка аккаунта хранит идентификатор | `linked_game_accounts.handle` по каждой игре |

## Раздел 9. Модель данных

| Сущность handoff | Таблицы портала |
| --- | --- |
| User | `users` (+ страна, цвет, реферальный код, email, онбординг), `wallets`, `xp_events`, `pass_*`, `objective_claims`, `user_cosmetics`, `linked_game_accounts`, `memberships` |
| Tournament | `tournaments` (формат, веса, best-of-N, срок, страны, награда), `registrations`, `roster_entries`, `matches`, `match_results`, `score_entries`, `tournament_organizers`, `tournament_sponsors`, `tournament_awards` |
| Team | `teams` (+ логотип и баннер), `team_members`, `team_invites` |
| Dispute | `disputes` (вид, доказательство, решение); место в сетке — через `matches.bracket/round/position` |
| Score log entry | `score_entries` (статистика с путём, флаги, решение, источник) |
| Challenge | `challenges` (вид `challenge` / `quick`, без поля ставки), `quick_queue` |
